# claude-math-tcs-agent

Multi-agent system for mathematical proof writing. The customer surface is `claude_prover/` — five proving agents — and is fixed. Everything else here is the backend that builds and maintains what those agents read.

## Architecture

```
claude_prover/      proving-agents (customer-facing, fixed)
      ↑ reads
skills/             same department as proving-agents — only what they consume
      ↑ generated by
phds/               bridge: organizer + regulator + knowledge DB
      ↑ ingests
distill/            multi-agent system that distills mathematician corpora
```

Information flows one way: `distill → phds → skills → claude_prover`. Skills exist to be read by proving-agents; nothing else drives them. Distilled knowledge does not become a skill until a phd promotes it.

## Tiers

- **`claude_prover/`** — five proving agents and their orchestration. Customer-facing; not modified by backend work.
- **`skills/`** — the actual snippets and style packs the proving-agents read at the point of need. Domain facts, written-style packs.
- **`phds/`** — one department with two roles (organizer, regulator) and a curated knowledge DB. Decides what crosses from distilled corpus into a skill.
- **`distill/`** — multi-agent backend. Reads raw mathematician corpora and produces distilled packs (heuristic minds for individuals, domain playbooks for batches).

Each tier has its own `README.md` with the layout and contract.
