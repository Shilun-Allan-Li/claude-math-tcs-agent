A proof attempt failed. You are given the statement, the attempt, and Lean's diagnostic.
Fix the proof.

**You may not change the statement**, for the same reason as before. If the diagnostic
convinces you the statement itself is wrong, reply with exactly
`STATEMENT_REVIEW_REQUIRED` and one paragraph of explanation.

Most failures at this stage are surface friction rather than mathematics. In the corpus
this pipeline was built from, nine of roughly fifteen build cycles in the one instrumented
session went to exactly these, and none went to a wrong proof idea:

- **a wrong name** — the lemma exists under a different one, or in a namespace;
- **two spellings of the same object** — `{{u}} : Set V` against the `Finset` coercion of
  the same singleton, which is the same set in two syntactic forms;
- **argument order** on a lemma applied with `apply`;
- **`motive is not type correct`** — rewriting a `set`-bound variable inside its own type;
- **an instance mismatch** — a `DecidableRel` or `Fintype` instance that does not match
  the one in scope, usually fixed with `convert` rather than `exact`.

Read the diagnostic literally before changing strategy. Changing strategy because of a
name error wastes the attempt.

Return only the corrected tactic block in a fenced Lean code block.
